11 为什么这么多 Agent Harness 都选择 TypeScript Moment 赞4/藏5/阅673 文章讨论为何 Claude Code、Gemini CLI、OpenCode、Pi 等 Coding Agent 的 Harness 常用 TypeScript，而不是人们一提 AI 就想到的 Python。作者把 Harness 理解成模型外面负责会话、上下文、工具调用、中断与恢复的那套程序，认为远程模型时代大量工作是请求、事件、工具和界面，Node.js 事件循环更贴这些 I/O 等待。文中强调很多功能会同时改到运行时、协议、状态和 UI，TS 便于共享类型；同时也指出 Codex 已转向 Rust，并提醒静态类型仍需配合 Zod 等运行时校验，因为模型返回的 JSON 并不保证符合接口定义。作者的结论不是 TS 唯一正确，而是何时这份便利值得保留、何时该换实现路线。 https://juejin.cn/post/7704455397478334499

11 为什么 Skill 很难商业化？Bot 才是 AI 时代真正的商业机会 前端小小栈 赞6/藏2/阅449 作者认为 Skill 解决的是 AI 能力复用，但用户买到的仍是能力配置，还要自己调用模型、补上下文、配工具和检查结果，因此很难单独形成稳定收费。文中给出三个障碍：价值难以独立衡量、替代成本越来越低、缺少完整交付闭环。相比之下，Bot 面向特定场景交付结果，用户不必理解底层 Skill 或 Agent 编排，也更容易按节省时间、订阅或按次收费，并在多个 Skill、MCP、知识库、记忆与调度组合后形成壁垒。作者的建议是：把 Skill 当作 Bot 的能力组件或面向开发者的基础设施，创业时更应卖能持续交付价值的 Bot，而不是卖提示词。 https://juejin.cn/post/7703881101718306825
14 土豆姐 Lauren 关于 Grok Bot 团队打造指南 XiaoLei_Liu 赞3/藏4/阅490 文章拆解 xAI Grok Bot 工程负责人 Lauren Tan（@poteto）的团队打造指南，并整理评论区补充。作者归纳的实战经验包括：先拉一个专门设计和审计其他 Bot 的「总监」Bot（dr eggbot）；少而精，几个好管的 Bot 胜过一支杂牌军；让 Bot 边干活边给自己写 Skills，甚至存进私有 GitHub；打通连接器与 Vault，必要时让 Bot 申请独立邮箱和账号以隔离权限；看见自己还在复制粘贴就反问 Bot 能否直接代劳；以及用带实习生入职的方式做自我介绍，让 Bot 自己提案自动化环节。文中还提到原帖里要求 Bot 用自己的话复述这一技巧。原帖：https://x.com/poteto/status/2116576229319233596 https://juejin.cn/post/7702895830278275123

13 10 分钟用 Docker 搭一套私有 Gitea：HTTPS、SSH、CI、备份一次配齐 废柴程序员_熊熊 赞2/藏4/阅186 作者因私有仓库月费、国内 clone 速度不稳，以及一次 CI 跑了约 40 分钟才发现是拉镜像卡住，把若干项目从 GitHub 迁到自建服务。文中给出的方案是四个容器：Gitea、PostgreSQL、Caddy、Runner；作者称在 2 核 2G 机器上空载内存约 200–300 MB，clone 能跑满带宽，CI 从推送到达成约 90 秒。数据库不用默认 SQLite，理由是并发写入容易 database is locked；目录需 chown 1000:1000 以匹配官方镜像里的 git 用户；版本号应钉死，不要用 latest，密码放在 .env 而不是 compose 文件里。 https://juejin.cn/post/7703381509637505039
14 GitHub 今日推荐｜auto-ontology：给 Agent 装上企业数据的语义索引 miofly 赞0/藏1/阅225 介绍 NVIDIA 开源项目 auto-ontology（https://github.com/NVIDIA/auto-ontology）：从企业数据库元数据生成语义本体，让 Agent 用业务术语提问并得到可追溯的 SQL。文章指出直接把 Schema 塞进 prompt 会碰到术语映射、token 预算和 JOIN 正确性三个障碍；该工具先编译术语表与关系，再用 pgvector 检索候选后生成 SQL，并在 coverage 不足时拒绝回答（文中举 ROAS coverage 0.5、提示缺少广告支出数据为例）。问答流程由 LangGraph 编排分类、检索、生成、校验与执行；Apache-2.0 许可，但 CONTRIBUTING.md 明确不接受外部贡献。前端/后端/摄取/MCP 端口分别为 3000/3001/3002/3003，自然语言转 SQL 依赖 NVIDIA API 密钥。 https://juejin.cn/post/7703895388126642203
