模型通过统一的聊天客户端和嵌入配置接入，密钥来自环境。不同任务可以指向不同模型：意图判断用较小的模型，复杂推理用较强的模型。

<!-- more -->

生产默认走兼容 OpenAI 协议的通义接口。地址和模型名都是占位，密钥不进仓库：

```yaml
spring:
  ai:
    openai:
      api-key: ${DASHSCOPE_API_KEY:${langchain4j.open-ai.chat-model.api-key}}
      base-url: ${DASHSCOPE_BASE_URL:https://dashscope.aliyuncs.com/compatible-mode}
      chat:
        options:
          model: ${DASHSCOPE_CHAT_MODEL:qwen-turbo}
      embedding:
        options:
          model: ${DASHSCOPE_EMBEDDING_MODEL:text-embedding-v4}
```

平台按任务再分一档默认模型。意图路由用较小的，推理用较强的，租户规则可以覆盖：

```java
public static class Model {
    private String intentRouting = "qwen-turbo";
    private String agentReasoning = "qwen-plus";
    private List<ModelRouteRule> routeRules = List.of();
}
```

功能上分三种调用：

| 用途 | 谁发起 | 怎么调用 |
| --- | --- | --- |
| 流式回答 | 知识问答、无工具的对话兜底 | `prompt` 指定系统和用户消息，`stream` 得到文本流 |
| 带工具的回答 | 智能体命中工具或外部工具协议时 | 先同步走完工具回路，再把整段结果适配成流。用来避开部分模型在流式工具调用上的不稳定 |
| 嵌入 | 文档入库、长期记忆 | 批量嵌入，维度与 pgvector 列一致 |

平台侧可以按任务类型注册模型，例如意图路由一套、智能体推理一套，并允许某个租户覆盖。名称改配置即可，对话代码不写死供应商。简单分类不要占用最贵的模型。

超时和重试放在客户端配置上。限流或暂时不可用时做有限次退避；多次失败则返回可理解的提示，并记下错误，而不是把供应商异常原样抛到页面上。

提示词模板放在资源文件里，用模板引擎替换变量，替换前检查变量是否为空。用户原文不直接拼进系统提示。日志记录追踪号和令牌用量，提示和工具参数要脱敏。用户输入过长时截断并告知，避免一次请求把上下文撑满。
