知识库按业务分库管理。上传文档时走一条启动时编译好的固定流水线：校验文件、解析、判断语言、分段、嵌入、落库。

<!-- more -->

一个库对应一块可单独授权的资料，例如制度或产品说明。库上有名称、说明、嵌入模型标识和租户。文档和切片挂在库下面。废弃文档标记为停用，检索时默认排除。

功能分两截。

库管理是普通用例：创建、更新、查询、删除知识库，补齐租户字段，做访问校验。它不调用模型。

文档上传是图。入口接收 multipart 文件，应用服务先做两道门：文件不合法直接拒绝；同时上传超过许可数量时返回冲突，避免嵌入把进程打满。通过后执行上传图，节点顺序来自配置，默认是：

1. 解析。用文档解析把原文变成稳定文本，去掉明显噪声。
2. 语言检测。结果写入状态，后面的分段和嵌入按这个语言处理。
3. 分段。长度和重叠读配置，当前中文约 500 字、重叠 100 字。代码按语言边界切，表格保留周围说明。
4. 嵌入。调用配置里的中文嵌入模型，批量提交，单批控制规模。向量维度必须和库一致，不一致应在启动或写入时失败，而不是静默截断。
5. 落库。写入文档行和切片行。切片保存正文、向量和最小元数据：来源、更新时间、文档类型、状态。

清洗放在分段之前：能去掉的个人敏感信息先去掉；去不掉的打上标记，留给检索之后过滤或在回答里提示。

节点顺序和分段参数都在配置里，图在启动时按这份列表编译：

```yaml
knowledge:
  chunk:
    max-chinese-chars: 500
    chinese-overlap-chars: 100
  upload:
    max-concurrent-uploads: 3
  graph:
    upload:
      nodes: [parse, languageDetect, split, embed, store]
```

进入图之前先占一个并发许可，占不到就直接失败。图执行完，无论成功与否都在 `finally` 里释放：

```java
if (!uploadSemaphore.tryAcquire()) {
    throw new IllegalStateException("上传并发数已达上限，请稍后重试");
}
try {
    OverAllState endState = graphBuilder.invoke(uploadGraph, inputs);
    return endState.value(KnowledgeGraphStateKeys.UPLOAD_RESULT)
            .map(GraphUploadResult::fromStateValue)
            .map(DocumentUploadResultMapper::toResponse)
            .orElseThrow(() -> new IllegalStateException("Upload graph did not produce result"));
} finally {
    uploadSemaphore.release();
}
```
