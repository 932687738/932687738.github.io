注册治理管的是「有哪些智能体、谁能用、花了多少、失败后能否续上」。一次问答的路由仍在对话模块，管理功能不插进那条流里。

<!-- more -->

注册表维护智能体条目和健康情况，并给每个智能体、工具打上权限标签。请求头 `X-User-Roles` 带上角色。对不上就返回拒绝，模型看不到这次调用：

```java
public Optional<ToolResult> checkToolPermission(String requiredTag) {
    if (!isEnforced()) {
        return Optional.empty();
    }
    Set<String> roles = PlatformUserContext.currentRoles();
    if (hasAdmin(roles) || roles.contains(requiredTag)) {
        return Optional.empty();
    }
    return Optional.of(ToolResult.fail(
            "FORBIDDEN", "缺少权限：需要 " + requiredTag + "，当前角色：" + String.join(",", roles)));
}
```

技能治理包括列表、发布新版本和冲突扫描。数据库里的技能和代码里编译好的图技能都出现在同一份清单里，执行时由技能服务按版本取定义。灰度可以让一部分流量走新版本。

提示词同样按版本治理：模板可以生成、保存、查看历史并回滚；实验按场景比较不同模板；常用模板可以收藏后再引用。对话渲染时读的是已经发布的模板，不在请求里临时改系统提示。

记忆和知识库分开，平台侧分三层：

| 层 | 功能 | 实现 |
| --- | --- | --- |
| 短期 | 当前几轮对话 | 跟会话走，问答后处理里更新 |
| 工作 | 一次技能执行的中间结果 | 跟这次技能走，结束即弃 |
| 长期 | 跨会话仍要召回的事实 | 按用户分区的向量，检索时带租户 |

三层记在同一张表里，用 `memory_type` 区分。长期记忆才建向量索引，工作记忆用内容键去重：

```sql
CREATE TABLE IF NOT EXISTS agent_memory (
    id              BIGSERIAL PRIMARY KEY,
    tenant_id       VARCHAR(64)  NOT NULL DEFAULT 'default',
    conversation_id VARCHAR(128) NOT NULL,
    user_id         VARCHAR(128) NOT NULL DEFAULT 'anonymous',
    memory_type     VARCHAR(16)  NOT NULL,  -- SHORT / LONG / WORKING
    content         TEXT         NOT NULL,
    embedding       vector(1024)
);

CREATE INDEX IF NOT EXISTS idx_agent_memory_long_vec
    ON agent_memory USING hnsw (embedding vector_cosine_ops)
    WHERE memory_type = 'LONG' AND embedding IS NOT NULL;
```

对话进行中的上下文另外绑在 `ChatMemory.CONVERSATION_ID` 上。把某次会话收成长期资料是另一个接口：按会话号取出记忆，再进入知识库的入库契约。置顶、分享和会话搜索写关系表和文本索引，不写这张记忆表。

费用按令牌估算，超过预算时由钩子告警。追踪把平台对话的跨度记到审计表，供回放，不写进回答正文。租户来自请求头，注册、技能、记忆、知识和费用都带租户条件。

飞书和外部命令行是入口，不是第四套治理。飞书长连接在启用且凭证齐全时订阅消息，按消息号去重，忽略机器人自己的回声。需要唤起本机编码助手时，走命令行用例：限制并发和超时，标准输出优先作为回发文本，助手不可用时降级成普通回执。命令行的可执行文件路径来自配置，未配置则这个入口直接失败，不影响站内对话。
