一次提问如何被分到具体智能体
意图路由 2026-10-26

智能体对话是一条 SSE：整理会话，给问题打分，选出子智能体或内置能力，再按编排计划生成回答。请求体只有会话号和消息，没有模式字段。

入口是智能体聊天接口。会话号为空时应用服务生成一个；否则去掉空白后沿用，保证多轮和后续的历史、置顶、分享指向同一次会话。

路由分两段，实现都在路由计划里，不散落在控制器。

第一段匹配已注册的子智能体。文本先规范化。每个子智能体自己声明关键词、排除词和优先级。命中排除词这轮分数为零；否则用关键词命中数，再加上专属词的加权：

取得分最高者；分数相同比优先级，再比名称。当前主要的子智能体是客服、数据分析和代码生成。

第二段在没有子智能体命中时走内置能力。时间日期、天气、文件读写会带上对应工具；政策或知识类问题打开检索；其余走通用兜底，不带检索也不带工具。这一段的产物是同一份编排计划：能力名、子智能体名、是否检索、允许的工具名、是否允许外部工具协议。

计划生成之后才检索。只有计划要求检索时，才按问题取有限条片段。然后组装对话上下文：会话号、被选中的智能体、片段、计划、可用工具。发布调用前事件，审计记下会话、智能体和能力。

预处理图把路由结果写成 streamRoute。应用服务按这个枚举分发，不再在控制器里写 if：

return switch (prep.streamRoute()) {
    case DIRECT_WEATHER, DIRECT_DATETIME -> Flux.just(prep.directAnswer());
    case SUB_AGENT -> delegateToSubAgent(prep);          // ReactAgent
    case ORCHESTRATOR, PLATFORM_ROUTER -> streamOrchestratorDirect(prep);
};
```聊天服务按计划从工具注册表取出本地工具和外部回调，并绑上以会话号为键的对话记忆。

有工具时同步跑完工具回路，再把完整答案变成一段流。没有工具时按令牌真流式输出。流正常结束发布调用后事件，异常发布错误事件。聊天接口把答案推回客户端，不在这条链上写向量库。
